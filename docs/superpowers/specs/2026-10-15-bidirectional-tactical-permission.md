# 黄金双向短线结构许可与AI自主入场

日期：2026-10-15。状态：**已按用户后续授权实现，离线验收见验证报告**。三盘定义已声明新许可；尚未启动交易或加载到正在运行的服务器。实际.env及存量持仓规则保持。

用户希望AI能够识别短线方向变化，不因较慢的H1标签持续向同一方向试单；最新补充明确要求BUY、SELL都覆盖。方案用于黄金模拟账户，保留现有本地粗筛、AI-1自主选机会、AI-2审核执行、AI-3护仓的分工。

## 1. 要改变的行为

H1背景方向与当前短线方向分开保存。H1仍按现有闭合收盘与EMA50比较，不改写其真实标签；新增可复核的M15结构方向，允许在有证据时提出逆H1的短线方案。

| 场景 | 允许AI评估的机会 | 不足以单独支持交易的理由 |
| --- | --- | --- |
| H1偏空，M15形成有效上涨结构 | 顺短线结构的BUY；上涨结构确认失败后，才恢复该段内的H1顺势SELL资格 | 只因H1偏空、一根M5上影或极小刺破便继续SELL |
| H1偏多，M15形成有效下跌结构 | 顺短线结构的SELL；下跌结构确认失败后，才恢复该段内的H1顺势BUY资格 | 只因H1偏多、一根M5下影或极小刺破便继续BUY |
| H1与M15有效结构同向 | 沿H1方向的自主机会 | 为增加候选数量再复制一份同向方案 |
| 行情数据合法，但没有有效M15反向结构 | 原H1方向的自主机会，AI也可观望 | 因为最近亏损或事后涨跌而自动反手 |
| 必要数据、来源或策略版本不合法 | 暂停新入场，持仓管理继续 | 将未知状态当成没有反证，从而放行 |

这是方向许可，不是自动入场信号。M15满足条件后，本地仍不直接下单；AI-1决定具体打法、真实触发、目标和是否值得做。回撤、延续、扫动回收、区域反应等仍由AI结合事实选择，不强制吞没、固定Fib区、RSI值或时段菜单。

## 2. 已知事实与取舍

依据[六笔SELL复核](../../experiments/2026-10-15-six-sell-entry-review.md)，10月15日六笔亏损SELL的成功AI-1输入均只有SELL候选，BUY被H1硬方向门排除。中间数笔在入场前已有M15上涨、低点抬升和更新M5回收证据。AI并不是对完整的BUY与SELL方案公平比较后选择SELL。

六笔是挑出的亏单，不是全部交易；当日还有两笔小盈利SELL。02:06不能提前看到02:15才闭合的M15，07:32也不能使用07:40后的上涨。设计不得以“这六处全部反手应盈利”为验收标准。应同时保留原来的盈利样本，以及与本次相反的下跌行情。

比较过三种处理：只提高置信度不能解决另一方向没有候选；全局取消H1约束会开放没有结构依据的逆势交易；本方案采用**显式、带版本的双向短线许可**，仅让启用该许可的三盘自主策略使用它。旧固定策略和缺少声明的策略继续原H1规则。

CME将前高低、均线等作为支撑阻力参考，并说明这些位置更接近区域而非精确价格；趋势变化需要结合价格行为判断。[支撑与阻力](https://www.cmegroup.com/education/courses/technical-analysis/support-and-resistance)、[趋势与延续形态](https://www.cmegroup.com/education/courses/technical-analysis/trend-and-continuation-patterns)支持这种背景与结构分开观察的思路。下述阈值、确认周期和状态机是本项目的**待验证假设**，不是这些资料提供的收益证明或作者算法。

## 3. 一个共享的方向引擎

新增纯模块`strategies/direction.py`，只接受已经闭合且时间合法的行情和明确的策略参数，不读.env、不访问MT5、不请求AI、不自行读取系统时间。主程序负责采样与身份核验；本地候选、AI事实、AI-2和最终下单都调用同一规则。

策略定义新增可序列化的`direction_policy`：

```json
{
  "version": "h1-or-m15-structure-v1",
  "break_lookback_m15": 2,
  "leg_ttl_m15": 6,
  "break_margin_atr": 0.10,
  "break_margin_ticks": 2,
  "failure_closes_m5": 2,
  "anchor_pivot_left_m5": 1,
  "anchor_pivot_right_m5": 1
}
```

初版参数在实施前登记，不根据六笔结果来回调参。BUY和SELL共用同一组参数，三盘也先共用；不设置夜间整段禁入或方向差异化门槛。缺省策略采用`h1-only-v1`；未知版本或不合法参数阻止新入场，不静默退回宽松规则。

### 3.1 M15结构事件

按时间顺序，对每根已闭合M15：

1. 用其之前两根已闭合M15的最高价构成上边界`U`，最低价构成下边界`D`。确认K线本身不参与计算这两条旧边界。
2. 容差`epsilon=max(0.10 × 该确认时刻的M15 ATR, 2 × tick_size)`。ATR沿用主系统的计算定义与完整预热，不能拿当前ATR冒充历史ATR，也不能从任意截短窗口重新初始化后声称数值相同。
3. 收盘严格高于`U+epsilon`形成上涨事件；严格低于`D-epsilon`形成下跌事件。仅影线突破、恰好等于边界、0.06之类没有通过尺度检查的刺破，不构成该结构事件。
4. 在最近六根闭合M15内选择**最后一个**合格事件。上涨事件若被之后任一闭合M15收在`U-epsilon`下方则失效；下跌事件若被收在`D+epsilon`上方则失效。失效后不恢复更早的旧事件。
5. 有效期从确认M15闭合起最多90分钟，到边界即过期。新的真实结构事件可以成为新的依据，普通请求或同一个事件重复读取不能续期。

输出`up/down/none/unknown`及原因。`none`表示足够且合法的数据中没有有效事件；`unknown`表示必要数据、ATR、tick网格、时钟或来源不可验证，两者不能合并。

H1本身仍须有合法bull/bear标签及原闭合来源。H1未知时不凭M15单独开放方向。新许可没有把未知背景当成任意交易的例外。

结构折叠需要覆盖最长有效期、ATR预热和前置边界；默认取完整已验证数据计算，仅压缩对外展示。输入存在相关时间缺口时，不能跨缺口拼成连续确认。新窗口追加未来K线，不得改变过去某时点的计算结果。

历史事件容差不使用当前点差冒充确认时点点差。当前点差、报价时效、追价与止损触发侧距离继续由实时执行门检查；若未来需要历史点差，须有真实采样来源后另行设计。

### 3.2 不再靠小影线反复对抗有效短线结构

H1与有效M15事件相反时，暂时限制H1同向方案：

| 有效事件 | 原H1方向重新具备资格的最小事实 |
| --- | --- |
| 上涨事件，H1偏空 | 确认事件之后，连续两根闭合M5均收在其冻结`U-epsilon`下方；或者M15事件已经按3.1失效/到期/被新事件替代，再重新计算方向许可 |
| 下跌事件，H1偏多 | 确认事件之后，连续两根闭合M5均收在其冻结`D+epsilon`上方；或者M15事件已经按3.1失效/到期/被新事件替代，再重新计算方向许可 |

两根M5必须连续，均在M15事件确认后开始，且实际突破冻结边界；不能拿确认前的M5拼成失败证据。恢复SELL时当前Bid须严格低于`U-epsilon`，恢复BUY时须严格高于`D+epsilon`；短暂报价穿越不替代收盘确认。

一旦某事件发生上述M5失败，就停止使用该事件支持原短线方向，直到有新的合格M15事件。失败证明按来源完整折叠，不因两根失败K线离开“最后两根”的展示窗口而消失。若价格已回到失败边界另一侧，但又没有新M15事件，冲突方向均等待，不用原事件来回翻仓。

只有一根反向M5、上/下影或一次报价回抽时，交给AI作为反证判断；它们不能单独通过上述H1恢复条件。恢复的是候选资格，仍需AI提出新交易理由和完整SL/TP，不自动反手、不在平仓时立即发单。

### 3.3 当前价必须仍支持所用结构

逆H1的短线BUY要求有效上涨事件未失败，最新Bid没有跌回`U-epsilon`下方；短线SELL镜像要求最新Bid没有站回`D+epsilon`上方。Bid用于与MT5 K线的同侧结构比较，BUY实际风险与RR另用Ask，SELL用Bid，不能混用。

报价已经穿越结构边界但收盘尚未确认时，暂停该结构的新增入场。已开仓不因此被入场模块自动平掉，其策略判断仍交AI-3，原SL/TP与本地保护继续执行。

## 4. 入场失效点必须与交易理由一致

方向事件与单笔保护点分别保存。看对大方向，不代表当前价有足够近且合理的失效点。

| 交易理由 | BUY保护依据 | SELL保护依据 |
| --- | --- | --- |
| 初始反转/起点保护 | M15事件的前两根与确认根最低点，再合并近三根M5低点及原缓冲/生成下限 | 同窗口最高点，再合并近三根M5高点及原缓冲/生成下限 |
| 结构形成窗口内的新局部回踩/反抽 | 左右各一根M5已闭合确认的更高低点，再合并近三根M5低点及原缓冲/生成下限 | 左右各一根M5已闭合确认的更低高点，再合并近三根M5高点及原缓冲/生成下限 |

支点搜索从该M15事件前两根边界K线中较早一根的开盘开始，包含结构形成过程中已出现的回踩/反抽，直到本次快照的最后闭合M5。左右邻居也须在此搜索窗口内，且右邻居已经闭合；不能使用更早别段走势或未来确认。这样，突破前已形成的真实局部支点不会仅因M15刚确认而被丢掉。

低点严格低于左右邻居才算低点，高点严格高于左右邻居才算高点。BUY局部低点须高于原事件起点至少`epsilon`，SELL局部高点须低于原事件起点至少`epsilon`。相等点不挑一根当拐点。

Python列出已确认、此后未被价格越过的支点，按确认时间选最近一个，形成该方向的规范保护依据；不得倒着寻找“刚好能塞进8美元”的支点。没有局部支点时只能采用原起点，不能补造一个。被后续K线极值越过或最新报价已破坏的支点不恢复为旧支撑/阻力。

每个方向最多一个候选。规范支点存在时，候选标明`local_pullback`；否则为`origin`。AI可以采用更保守的原起点或更远的真实保护，不能采用更近的保护。局部方案的文字理由必须明确只交易这次新回踩/反抽的延续，不能同时宣称原大级别起点被完整保护。

BUY的SL不得高于`min(规范保护低点, 近三根M5最低点)-stop_buffer`；SELL的SL不得低于对应最高点加缓冲。原生成风险下限、最终价格舍入和触发侧净距仍独立执行。覆盖后风险大于8就等待/拒绝，不能把SL向内裁。

示例：02:26若BUY必须保护4080.34起点，加原缓冲到4079.34，从Ask4092.26计算风险12.92，仍不能开。02:20–02:25的低点在02:26尚无右侧闭合确认，不可提前当成新支点。后续新的合法支点可能产生另一笔方案，但这不是把原方案的止损挪近。

“原H1方向在M15结构失败后恢复”的方案，先固定最早完成失败确认的那两根连续M5：BUY至少保护这两根的最低点，SELL至少保护最高点，再合并原近三根M5极值、缓冲和生成下限。后续若有新的局部方案，须有新的已确认支点与真实检查点，不能为同一提案更换保护依据。H1与M15同向或合法none时的普通H1路线保留原止损规划，不额外强加一个不存在的反转起点。

目标仍需真实依据。向AI同时给出计划TP的RR、到最近反向障碍的距离/RR和需要穿越的区域。AI应解释为何越过障碍仍合理，或将目标放在障碍前；没有空间就观望。不能将每一根影线都机械升级为“首障碍也必须1.5R”，也不能把计划3R当成已实现收益。最低成交RR1.5及原目标上限保持。

## 5. 三个AI如何使用

### AI-1：一次请求比较两边事实，选择一个方案

共享事实包括真实H1背景、M15事件/失败证据、两个方向的价格行为、保护依据、反向障碍及近期已结算交易。每个方向明确说明`allowed/blocked`及机器计算原因；有合法候选时才按原调度请求AI，空池写本地原因，不付费请求一个不可能执行的方案。

原顺H1机会和新增短线机会共用候选池，不另发一轮“找反向机会”的HTTP。AI仍返回原`opportunity_id`、动作、SL/TP、触发、失效条件、目标依据及现有质量卡。许可版本、结构事件和保护来源由Python随候选提供，AI无需再生成一套方向评分或新嵌套契约。

提示词要求同时考虑最新支持事实和最强反证。允许把真正轻微的反证列为观察；不得仅因H1同向便忽略已确认的相反短线结构，也不得把每根反向K线强行定为重大扣分。质量规则继续`entry-quality-v4`，同一原因与事件只声明一次，不通过自动改等级/修引用/把no改交易来提高通过率。

### AI-2：核原方向依据与当前执行条件

每个实际POST前取新报价和闭合来源，重新验证**原候选**许可、原事件、规范保护与固定SL/TP。逆H1不是错误，只要原方案带合法新版本证明；缺证明的逆H1仍拒绝。H1顺势但M15冲突时，必须有原失败证明。

AI-2不反向改单、不把旧BUY改SELL、不自动换支点或重写SL/TP。新M5/M15导致原检查点过期、指纹改变、结构被破坏或当前RR不够时拒绝这份提案，等待下一次原调度；不付费重审残缺/截断/正常拒绝。

### AI-3：守这笔单原本交易的结构

保存实际成交价、原SL/TP、实际许可版本、H1背景、所选结构事件、保护依据及失效理由。BUY和SELL使用镜像证据判断hold/tighten/close。逆H1本来就是入场时已知事实，不能一收到bear/bull标签就机械平仓。

入场许可过期或候选检查点到期，不是持仓理由自动失效；也不能用当前新策略重建旧持仓。后续结构变化交AI判断，原SL/TP、`profit-floor-v2`单向减亏/锁盈、噪声空间与`holding-review-v1`继续。这个设计不改变护盘频率、不新增付费护盘调用、不放宽SL、不加仓。

## 6. 近期交易反馈：同时呈现赚与亏

只从`settle_position_deals`确认完整生命周期的历史成交接收结果。新增独立、有限的本地交易上下文缓存，按账户/服务器隔离标识、symbol、magic分区，幂等键为position_id与成交ID集合；保存实际开平仓、净盈亏、已核实平仓原因及原方向依据，最多64笔。

入场快照提供最近6小时内最多6笔**全部方向、全部盈亏**的精简事实；按已确认的UTC时间筛选，无法可靠转换的时间不参与该窗口。无历史/重启不完整/缓存失败时标明覆盖范围与不可用原因，不拿最后浮盈、余额差、“持仓消失”或推测原因填充。本功能不制造原来已删除的“未知盈亏”通知。

缓存是软参考；写入失败不绕过现有关键交易状态的失败保护，也不自行强制停止其他合法机会。原交易ledger的预留/恢复规则保持严格。AI可据同一结构反复失败重新审视判断，不能按亏损次数自动翻方向、提高某一侧门槛、倍增仓位或追损。

## 7. 契约、来源与并发边界

方向事实在请求中的展示分为公共`direction_context`和单候选`direction_permission`。公共部分只含可共享的行情事实/来源，不包含另一候选的计划、质量卡或私有宿主字段。

`strategies/citations.py`仅为明确声明的公共事实路径及所选候选生成引用目录；同时更新Schema、提示词与Python校验。保持短ID绑定**该次成功POST**，保留原候选与方向隔离，不把整个新根节点递归放入通用白名单。BUY可以引用共同的下跌事实作为反证，不能借此引用另一SELL候选的SL/TP/质量结论。

宿主保存不可由AI填写的验证记录：`policy_version/parameters_digest/engine_digest/strategy_fingerprint/structure_event_id/route/action/source_bar_ids/source_digest/epsilon/anchor/proof_digest`。引用目录只展示公开事实。JSON字段结构、事实有无、方向、时间和来源一律严格验证，不按相近价格、相似路径或最近持仓猜测。

每次AI-1重试刷新完整事实与目录，以成功POST冻结方案。AI-2与最终发送前重验原证明和当前报价；不能悄悄把同一提案迁移到新事件/新支点。辅助模块加入加载代码签名并要求重启，定义参数仍用原内容指纹重载；不宣称辅助模块可即时热更新。

原检查点派发与订单预算按**同一账户/品种/策略范围的M5/M15检查点**共享。route、direction、anchor或候选ID变化均不重置普通派发/订单尝试预算，不能先试SELL失败再以BUY候选同轮多下。保留跨策略既有预留约束、单仓检查、原子预提交消费、不确定回执消费和精确token恢复。

同一结构可在之后真实新检查点评估机会，沿用60秒平仓冷却；不开同检查点的“反手重试”通道，不新增恢复最近价格订单的捷径。

## 8. 必须贯通的代码入口

实施时不得仅改提示词或`evaluate_profile`。当前可见H1限制分布如下，均须按同一许可验证器改造，并回归旧策略：

## 9. 保持的约束

仅DEMO、0.01手、最多1仓；SL绝对值8、成交RR至少1.5、最近三根M5极值加原缓冲、EMA21追价1.5ATR和实时触发侧2倍buffer均保留。质量阈值以实际.env为准，BUY/SELL相同，不修改本地/AI门槛、模型、档位、超时或6144上限。

新闻发布时间前后各15分钟暂停新入场；原SL/TP、本地锁盈及AI-3继续。主备/兼容处理共用原5次POST预算、每POST新快照、读超时成本保护、超上限配置暂停、截断不交易均保持。

不增加D1/H4方向硬过滤、不以六个亏损点拟合整段夜间禁入、不自动止损反手、不用更宽止损替代入场判断。不修改crypto_demo或local_guard_demo。

## 10. 验收与上线顺序

1. **先验证方向与来源**：用镜像、边界、缺口和未来数据隔离测试，证明过去结果不依赖后来的K线；上涨BUY与下跌SELL使用完全镜像的许可、保护和失败恢复。
2. **再验证完整工程通路**：离线伪造AI完整回复，证明合法逆H1的BUY与SELL能贯通全部门；缺证明、旧模式、失效支点、过期来源、跨候选引用和变更指纹不能绕过。验证AI-2每次重试及最终下单前的行情变化。
3. **再复核整段历史**：包括10月15日全部八单、观望检查点及可用的相反走势日期，比较候选/阻断原因；不能只挑六个亏损点。历史没有BUY/SELL对应的真实AI回复时，不构造“AI本会盈利”的收益曲线。
4. **完成后才能准备模拟部署**：新许可只作用于新提案/新仓，存量仓和旧策略保留原契约。工程验证通过不是收益结论，也不以历史盈利作为用户已授权的模拟探索前置门。
5. **后续固定参数观察**：按全部交易记录方向、盘段、许可路线、成交频率、零成交时段、净盈亏、回撤、平均盈亏、连续亏损、AI成本与请求失败。与原版本同口径汇报，不保证每天或每方向强行开够单，不把样本内择优写成胜率提升。

具体实施顺序见[实施计划](../plans/2026-10-15-bidirectional-tactical-permission.md)。当前运行系统仍为原H1方向限制，本文不代表服务器已经具备双向短线许可。


实施结果及诊断见[双向许可验证](../../experiments/2026-10-15-bidirectional-validation.md)。初版v1只接受登记的八项参数值，变更该机制须显式升级已支持的契约；现有目标/菜单/评分参数仍走原内容指纹检查。
