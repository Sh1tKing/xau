# 报告候选接入三AI模拟盘

用户要求使用黄金策略研究报告中的策略。选用报告优先候选session_retest：伦敦与纽约当地08:00–08:30的六根连续已收盘M5建箱，宽度1–6个该窗口末根M5 ATR；08:30–11:00内第一次收盘越过边缘0.05ATR，随后六根M5/30分钟内首次触及边缘0.25ATR并收盘守在外侧0.05ATR。回收箱内0.30ATR即失效；只能使用最新已收盘M5的首次回踩确认，不追错过的确认。窗口按当地日期和IANA时区标识，处理夏令时。

## 全局约束

- 仅模拟账户启用；旧三个定义保留但默认关闭，只运行研究候选，不混合旧策略结果。
- 本地粗筛、AI-1自主提案、AI-2审核、AI-3护盘不变；AI不能绕过时段/首次事件等策略硬条件。
- 保留H1同向、SL≤8、RR≥1.5、M15 EMA21偏离≤1.5ATR、最近三根M5影线保护、0.01手和最多一仓。
- 新候选单独使用确认M5收盘参考价及最近三根M5极值保护，参考目标上限3R；不将旧策略的M15参考价全局改成M5。生产保护缓冲和最低距离保留，明确与独立研究不同，不复用研究收益结论。
- 每伦敦/纽约日期窗口最多一次下单尝试，事件状态在发送订单前持久化，失败不追该窗口；10分钟全局冷却、最长持有180分钟，由Python执行，AI不得取消。
- 时段外、窗口不完整、时差未知、事件已用或无新确认时停止新入场，已有持仓继续原入场契约护盘；不额外付费请求AI。
- 不修改实际.env的模型、档位、超时、门槛或Messages协议，不启动/重启任何交易或MT5进程，不主动推送。

## 实施任务

1. 纯函数实现时段建箱/首次突破/首次回踩事实，覆盖夏令时、缺失K线、失效、错过确认、买卖镜像及前缀不变。与研究规则逐条对照。
2. 框架增加显式时间输入、参考价/保护来源及生命周期声明；新增session_retest定义，关闭旧三个默认启用项。实时通过tick与采集时刻核实时差，离线使用历史metadata；不靠最新K线反推不可靠时差。
3. 接通本地、AI快照/最终定稿/下单前校验与持仓护盘：事件状态持久化、模拟盘校验、冷却与180分钟退出；回测使用同一策略声明和事件限制。保留旧仓上下文，不因新策略切换停止护盘。
4. 运行离线回归、内置自检和固定历史生产口径回测；记录实际接入后的信号、拒绝与收益，不优化历史参数求漂亮曲线。任务代码复核、修复、提交本地master；同步server_deploy完整策略包与manifest，写回agentmemory。
