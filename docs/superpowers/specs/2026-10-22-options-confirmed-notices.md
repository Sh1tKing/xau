# 期权新机会只推送已核验的具体币安合约

用户明确要求：分析充分比速度重要，预计持有 1–3 天；长方向研究卡太多，仅确认具备买入条件时发通知，必须列出哪天到期、看涨/看跌、哪个行权价，且由币安查询确认。

## 执行路径

`options_analysis/engine.py` 的自动路径保留 MT5 主分析。WAIT/WATCH 直接保存且静默。CONSIDER 后仅从独立 `PublicOptionQuotes` 的四类无鉴权 GET 取得真实元数据、指数、IV、双边盘口；不接账户和交易接口。

公开查询关闭、读取器缺失、网络/元数据失败或初始基差不合格，保存 `option_unavailable`。期限、流动性、预算或慢兑现/IV 回落目标情景没有候选，保存 `no_suitable_option`。两者均保留原始主分析和具体原因，`review=None`，不调用方向研究 REVIEWER、不生成新买入通知或建议状态。这消除了旧流程缺合约仍付费复核并发送长研究卡的回退。

有候选时保留完整独立 REVIEWER。审核必须选择本次枚举中的唯一完整合约代码，不能改变方向/目标/数量/价格上限。拒绝不换合约付费重审。审核后重新读取原合约的元数据/状态、指数、IV、双边盘口及 MT5 身份/tick，保留期限、原预算/数量/权利金上限、基差、新闻、触发和成本门。

最终成功结果标 `confirmed-binance-option-v1`。`validate_buy_notice` 在建立通知去重状态及建议之前，核对原始/最终公开事实来源、资产、唯一完整合约身份、独立审批与所选代码、原候选身份、最新盘口事实一致性、期限/鲜活度、原 MT5 来源与触发、数量/价格/深度/成本。旧只有 `consider` 字符串、研究卡、合成数据或单个布尔标记不能发送。通知文本由验证后的数值字段生成，不采用模型自由文本；到期时刻用真实 `expiryDate` 转完整北京时间，行权价和权利金避免 `:g` 的六位有效数字截短。

## 输出和调用成本

买入卡仅列实际到期日、方向、行权价、完整代码、真实买一/卖一、最高接受权利金、核验/有效时间、MT5 触发/失效/第一目标、预计兑现/复核、数量/估计成本和最大损失。详细分析、反证、方法条件、独立审核及全部情景仍保存在 SQLite，按分析编号查看。

普通扫描失败记录 SQLite/stdout，不发飞书；WATCH 也不受旧 `OPTIONS_NOTIFY_WATCH=true` 开启。已发建议的撤销、已显式录入持仓的退出/到期/来源提醒保留，不自动建立持仓或执行平仓。历史研究卡及人工账本按原版本兼容；保留显式旧研究方法只供兼容，不再是自动分支。干跑不消费通知状态。

模型仍须完整分析和验证证据，只将可见中文叙述目标调为约 500 字（WAIT/WATCH 约 250），不重复抄行情；必要引用、反证、退出条件和完整 JSON 不因字数目标省略。不降低现有 token 上限、模型/档位、600 秒主备等待、1800 秒研究预算或鲜活/偏移门。缩短飞书文本本身不减少模型费用；取消无合约时的额外复核是可验证的 POST 减少，真实 token/费用及合约机会质量仍看实际 usage 和服务器记录。
