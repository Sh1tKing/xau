# AI 请求行情刷新与执行复核

用户确认：每次实际重试都必须提交当前实时价格。此次保持本地策略、M15 参考价、AI 自主提案、AI-2 审核和 AI-3 护盘分工，以及现有模型、档位、门槛和 HTTP 请求预算。

1. `call_chat` 增加可选请求构建回调，在每次实际 POST 前调用，包括主备切换和参数兼容恢复；普通字符串调用保持兼容。回调失败或任务失效不发送旧请求。每次记录快照编号、报价和采集时间。
2. AI-1 每次请求重新读取已收盘 H1/M15/M5、本地评分和 Bid/Ask，重新生成一致的证据包。返回的提案、评分卡和 Python 定稿必须使用该次请求的快照。
3. AI-2 每次请求重新读取报价并重算固定方案的执行区间与可行性，保留 AI-1 原快照编号/报价供对照。若出现新的已收盘 H1/M15/M5，旧提案停止审核，等待下一轮重新分析，不给旧评分卡替换证据。
4. 执行区间由固定 SL/TP、既有 `entry_risk_limits(atr)` 和 RR>=1.5 推导，不移动 SL/TP。当前止损触发侧价格还须留出既有 `stop_buffer(atr)` 保护空间。AI-2 接收这些事实；Python 在下单前再次检查相同条件及实时 EMA21 追价限制。AI-2 返回期间新增收盘K线也停止执行。
5. AI-3 重试重新读取原持仓的当前报价、持仓状态、收盘K线和护盘证据；原持仓消失则停止，不让旧请求接管另一个新仓。
6. 基础下单函数提供实时校验钩子，三 AI 模式应用上述检查；纯本地策略评分/参考价和回测规则不改。开仓通知使用订单回执中的真实成交价，回执未返回价格时标明未知，明确区分提交报价。

不增加同通道读超时补发，不因 no/REJECT 或截断重新请求，不扩大入场区间或放宽止损。离线回归覆盖重试报价变化、快照绑定、AI-2 更新、旧K线审核过期、历史秒损案例、BUY/SELL 对称性及 AI-3 持仓变更。同步部署脚本，保留部署 `.env` 和日志；代理不启动交易进程。
