所有实际POST继续共用原总预算和逐次行情刷新，跳过不写为已付费HTTP；usage增加`read_timeout_stage`和`primary_temporarily_bypassed`。原单次超时没有缩短，上游超时后可能继续生成计费的事实也没有改变。AI2/AI3不启用这个跨任务暂避政策。

## 新一周日历

`news-coverage-v1`合并运行缓存和启动备用，连续有效截止同时受`coverage_until`与`verified_at+7天`约束，明确cache/bootstrap来源；相接的已核对覆盖可跨周拼接，有缺口则停止覆盖。不能只看当周缓存，也不能因为一个年度日历的结束日期较远就无限续命。成功刷新时，临近覆盖末端会提前再次后台刷新，HTTP不占持仓护盘路径。

新增只读检查示例：

```powershell
python -m strategies.news_calendar --through 2026-10-24T07:00:00+08:00
```

加`--refresh`才访问公开来源并写日历缓存；`--through`检查的是日历数据覆盖，不表示新闻休息窗口内允许开仓。CLI使用进程环境变量及默认缓存路径，不加载或打印AI密钥；自定义`FIB_PA_NEWS_CALENDAR_CACHE`需显式传入进程环境。

本地重新核对的有期限启动日程已覆盖至北京时间24日07:00，核对有效期截止24日14:54:15。BLS直接HTTP仍403，日期由[官方十月列表](https://www.bls.gov/schedule/2026/10_sched_list.htm)通过网页工具核对；BEA与Fed分别从[官方发布JSON](https://apps.bea.gov/API/signup/release_dates.json)、[官方十月月历](https://www.federalreserve.gov/newsevents/2026-october.htm)实际HTTPS取得并解析。不能称BLS直接下载已修好，也不能称服务器已有这份新日程。过去14日启动备用可至21日晚，原周复盘中“18日缓存到期导致周一必停”的解释已更正。
